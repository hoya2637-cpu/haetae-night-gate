## 4. 여유(slack)를 판정에서 제거한 이유

**단순히 삭제한 것이 아닙니다. 실제 런타임에서는 검증력이 없는 지표임을 실측으로 확인하여 PASS/FAIL 기준에서 제거하고, 진단용 계측으로 용도를 변경했습니다.**

두 단계로 드러났습니다.

**① 실제 도달 웨이브 기준 — 구조적으로 항상 참**

러너는 벽 직전까지만 갑니다. 따라서 마지막으로 넘은 웨이브는 반드시 45초 이하이고
여유는 정의상 1.0 이상입니다. 실측에서 **4인 전부 정확히 1.00**이 나왔습니다.

**② 설계 목표 웨이브 기준 — 적합 오차를 붕괴로 오판**

여유는 웨이브 차이를 지수적으로 증폭합니다(HP가 웨이브당 9% 증가).

```
설계보다 8웨이브 뒤처짐  →  여유 = 1 / 1.09^8 = 0.50
```

재적합 곡선의 정상적인 ±4% 진동이 '미달'로 잡혀, 헤비 유저는 **540런 중 364회(67%)**가
미달로 표시됐습니다. 실제로는 같은 회차에서 일반 유저와 도달 웨이브가 동일합니다.

→ 설계 대비 진행은 **웨이브 비율**로 잽니다. 실측 1.05 / 1.04 / 1.01 / 0.99 / 0.96.

## 8. 이번 P0의 교훈 — 통과하는 테스트 ≠ 검증력 있는 테스트

같은 유형의 문제를 **세 번** 만났습니다.

| # | 테스트 | 왜 무의미했나 |
|---|---|---|
| 1 | `ValidateOfflineIntegrity` | 비율 < 1이면 `StartWave = lastWave + log(ratio)/log(1.075) < lastWave`. 수학적으로 항상 참 |
| 2 | 여유 ≥ 1 (실제 도달 기준) | 러너가 벽 직전까지만 가므로 정의상 항상 참 |
| 3 | 설계 미달 = 온보딩 | 실제 원인은 온보딩 + **승천 직후**. 가정이 좁았음 |

셋 다 **통과하고 있었거나, 통과하도록 만들기 쉬웠습니다.**
검증 체계의 목표가 *"테스트가 통과하는가"*에서 *"그 테스트가 실제로 무엇을 검증하는가"*로
옮겨간 것이 이번 작업의 가장 큰 성과입니다.

부수적으로 **밴드를 실측 없이 정하면 반드시 틀린다**는 것도 반복 확인했습니다.
체력 1.12(절대 밴드 → 실측 기반), 60런 정체 기준(계측 후 결정) 모두 그렇습니다.
